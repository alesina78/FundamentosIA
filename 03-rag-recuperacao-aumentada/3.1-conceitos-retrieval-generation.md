# 3.1 — Conceitos: Retrieval + Generation

> **RAG (Retrieval-Augmented Generation)**: técnica que busca informação relevante em uma
> base de conhecimento externa e injeta essa informação no prompt antes de pedir ao LLM
> que gere uma resposta — em vez de depender só do que o modelo "sabe" do treinamento.

## O problema que o RAG resolve

Como vimos no módulo 1, um LLM só "sabe" o que estava no seu treinamento — e mesmo assim,
não com precisão perfeita (alucinação). Isso é um problema quando você precisa que o
modelo responda sobre:

- **Dados privados/internos**: documentação da sua empresa, políticas internas, catálogo de produtos.
- **Informação recente**: eventos após o corte de conhecimento do modelo.
- **Fatos muito específicos**: onde uma alucinação seria inaceitável (ex: política de reembolso).

RAG resolve isso **sem re-treinar o modelo**: você busca os trechos relevantes de uma base
de conhecimento e coloca esses trechos diretamente no prompt, junto com a pergunta.

## O fluxo básico do RAG

```
Pergunta do usuário
        │
        ▼
  1. RETRIEVAL — buscar documentos relevantes na base de conhecimento
        │
        ▼
  2. AUGMENTATION — montar um prompt com a pergunta + os documentos encontrados
        │
        ▼
  3. GENERATION — o LLM gera a resposta usando esse contexto
```

O passo crítico é o **retrieval**: se a busca trouxer documentos irrelevantes, a resposta
do modelo também será ruim (efeito "garbage in, garbage out"). Os módulos 3.2 e 3.3 cobrem
como fazer essa busca de forma eficaz com embeddings e chunking.

## Exemplo em Python — RAG manual, sem vector database

Para entender o conceito antes de adicionar a complexidade de embeddings, este exemplo faz
a "busca" com uma técnica simples (sobreposição de palavras) — na prática você usaria busca
vetorial (aula 3.2), mas o fluxo geral é idêntico.

Código completo: [`exemplos-python/3.1_rag_manual_simples.py`](exemplos-python/3.1_rag_manual_simples.py)

```python
def responder_com_rag(pergunta: str) -> str:
    contexto = buscar_documentos_relevantes(pergunta, documentos)
    contexto_formatado = "\n".join(f"- {doc}" for doc in contexto)

    prompt = f"""\
Responda à pergunta do cliente usando APENAS as informações abaixo. Se a resposta não
estiver nas informações fornecidas, diga que não tem essa informação — não invente.

Informações disponíveis:
{contexto_formatado}

Pergunta do cliente: {pergunta}
"""
    ...
```

Note a instrução explícita **"use APENAS as informações abaixo"** e **"não invente"** — isso
ancora a resposta no contexto fornecido e reduz (não elimina) o risco de alucinação.

## Pontos-Chave

✅ RAG combina busca (retrieval) com geração (generation) para ancorar respostas em dados reais.
✅ Resolve o problema de dados privados, recentes ou muito específicos sem re-treinar o modelo.
✅ A qualidade do retrieval determina a qualidade da resposta — busca ruim = resposta ruim.
✅ Instruir o modelo a responder "apenas com base no contexto fornecido" reduz alucinação.
