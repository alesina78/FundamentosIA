# 3.2 — Embeddings e Vector Databases

> **Embedding**: uma representação numérica (um vetor de centenas/milhares de números) de
> um texto, gerada por um modelo, de forma que textos com significado semelhante ficam
> "próximos" nesse espaço vetorial.

## Por que embeddings em vez de busca por palavra-chave

A busca por palavra-chave (como no exemplo "manual" da aula 3.1) falha quando a pergunta
usa palavras diferentes do documento, mesmo tendo o mesmo significado:

```
Pergunta: "Posso trocar uma roupa que comprei há uma semana?"
Documento: "Trocas de tamanho em roupas são gratuitas dentro de 15 dias da entrega."
```

Nenhuma palavra em comum além de "roupa" — uma busca por palavra-chave simples pode não
encontrar esse documento. Embeddings capturam **significado semântico**: a pergunta e o
documento ficam próximos no espaço vetorial mesmo sem compartilhar as mesmas palavras.

> 💡 Para visualizar de forma interativa como embeddings se agrupam por significado em um
> espaço vetorial (reduzido para 2D/3D), explore o
> [TensorFlow Embedding Projector](https://projector.tensorflow.org/) — ele plota milhares
> de embeddings e permite ver quais ficam próximos uns dos outros, ajudando a criar
> intuição sobre o que significa "distância semântica".

## Similaridade de cosseno

A forma padrão de medir "quão próximos" dois embeddings são é o **cosseno do ângulo**
entre os dois vetores — quanto mais próximo de 1, mais similares semanticamente.

```python
def cosseno(a: list[float], b: list[float]) -> float:
    produto_escalar = sum(x * y for x, y in zip(a, b))
    norma_a = math.sqrt(sum(x * x for x in a))
    norma_b = math.sqrt(sum(y * y for y in b))
    return produto_escalar / (norma_a * norma_b)
```

## De onde vêm os embeddings

A Anthropic **não** oferece um endpoint próprio de embeddings — a parceira recomendada
oficialmente é a **Voyage AI**, que tem modelos de embedding e um free tier para começar
(voyageai.com). Outras opções: modelos open-source rodando localmente (ex: via
`sentence-transformers`), ou embeddings de outros provedores.

## Exemplo em Python — busca por similaridade semântica

Código completo: [`exemplos-python/3.2_embeddings_similaridade.py`](exemplos-python/3.2_embeddings_similaridade.py)

```python
def buscar_por_similaridade(pergunta: str, documentos: list[str], top_k: int = 2) -> list[str]:
    embeddings_docs = vo.embed(documentos, model="voyage-3.5", input_type="document").embeddings
    embedding_pergunta = vo.embed([pergunta], model="voyage-3.5", input_type="query").embeddings[0]

    pontuados = [
        (cosseno(embedding_pergunta, emb_doc), doc)
        for emb_doc, doc in zip(embeddings_docs, documentos)
    ]
    pontuados.sort(key=lambda x: x[0], reverse=True)
    return [doc for score, doc in pontuados[:top_k]]
```

Note o parâmetro `input_type`: `"document"` para o que será indexado, `"query"` para a
pergunta de busca — alguns modelos de embedding otimizam a representação de forma diferente
para cada papel.

## Vector databases

Calcular similaridade em Python puro (como acima) funciona para poucos documentos, mas não
escala — buscar entre milhões de vetores exige um **vector database**, otimizado para
busca por similaridade em alta dimensão.

| Vector DB | Características |
|---|---|
| **Chroma** | Open-source, roda localmente, ótimo para prototipar e projetos pequenos |
| **Pinecone** | Gerenciado (SaaS), fácil de escalar, free tier disponível |
| **Weaviate** | Open-source ou gerenciado, suporta busca híbrida (vetorial + palavra-chave) |
| **pgvector** | Extensão do PostgreSQL — bom se você já usa Postgres e não quer outro serviço |

Na prática, o fluxo com um vector database é: gerar o embedding de cada documento uma vez,
armazenar no banco; a cada pergunta, gerar o embedding da pergunta e pedir ao banco os `N`
vetores mais próximos — o banco faz a busca de forma otimizada (índices como HNSW), sem
precisar comparar contra todos os vetores um a um.

## Pontos-Chave

✅ Embeddings capturam significado semântico, não só sobreposição de palavras.
✅ Similaridade de cosseno é a métrica padrão para comparar dois embeddings.
✅ A Anthropic não tem endpoint de embeddings — a parceira recomendada é a Voyage AI.
✅ Para bases de conhecimento grandes, um vector database (Chroma, Pinecone, pgvector...) é necessário para buscar com eficiência.
