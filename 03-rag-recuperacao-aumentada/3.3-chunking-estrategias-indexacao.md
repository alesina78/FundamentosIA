# 3.3 — Chunking e Estratégias de Indexação

> **Chunking**: o processo de dividir documentos longos em pedaços menores ("chunks")
> antes de gerar embeddings e indexar — porque embeddar um documento inteiro perde
> granularidade e pode estourar limites do modelo de embedding.

## Por que dividir documentos em chunks

Se você gerar um único embedding para um documento de 50 páginas, esse vetor tenta
representar "a média" de tudo — perguntas sobre uma seção específica não vão casar bem com
esse embedding genérico. Dividir em chunks menores permite que cada pedaço tenha um
embedding mais fiel ao seu conteúdo específico, melhorando a precisão da busca.

Mas chunks pequenos demais também são um problema: cortam o contexto no meio de uma ideia,
e o modelo de geração recebe um trecho incompleto.

## Duas estratégias comuns

### 1. Tamanho fixo com sobreposição

Divide o texto em blocos de N caracteres (ou tokens), com uma sobreposição entre blocos
consecutivos para não perder informação que ficaria cortada na fronteira.

```python
def chunk_por_tamanho_fixo(texto: str, tamanho: int = 500, sobreposicao: int = 50) -> list[str]:
    chunks = []
    inicio = 0
    while inicio < len(texto):
        fim = inicio + tamanho
        chunks.append(texto[inicio:fim])
        inicio += tamanho - sobreposicao
    return chunks
```

**Vantagem**: simples, previsível, funciona em qualquer tipo de texto.
**Desvantagem**: pode cortar no meio de uma frase ou ideia, ignorando a estrutura do documento.

### 2. Por estrutura (parágrafos, seções)

Respeita a estrutura natural do documento — agrupa parágrafos inteiros até atingir um
limite de tamanho, sem cortar no meio de uma unidade de sentido.

```python
def chunk_por_paragrafo(texto: str, max_chars_por_chunk: int = 800) -> list[str]:
    paragrafos = [p.strip() for p in texto.split("\n\n") if p.strip()]
    chunks = []
    chunk_atual = ""
    for paragrafo in paragrafos:
        if len(chunk_atual) + len(paragrafo) > max_chars_por_chunk and chunk_atual:
            chunks.append(chunk_atual.strip())
            chunk_atual = ""
        chunk_atual += paragrafo + "\n\n"
    if chunk_atual.strip():
        chunks.append(chunk_atual.strip())
    return chunks
```

**Vantagem**: preserva unidades de sentido completas — melhor qualidade de embedding.
**Desvantagem**: chunks de tamanho variável; documentos sem estrutura clara (parágrafos
mal definidos) não se beneficiam tanto.

## Como escolher o tamanho do chunk

| Tamanho do chunk | Quando usar |
|---|---|
| Pequeno (100-300 tokens) | Perguntas pontuais, respostas curtas e específicas (ex: FAQ) |
| Médio (300-800 tokens) | Caso geral — bom equilíbrio entre precisão e contexto |
| Grande (800+ tokens) | Perguntas que precisam de mais contexto ao redor (ex: análise, resumo) |

Não existe um tamanho "certo" universal — o ideal depende do tipo de documento e das
perguntas que os usuários fazem. Na prática, vale testar mais de uma estratégia e comparar
a qualidade das respostas finais.

## Pontos-Chave

✅ Chunking existe porque embeddar um documento inteiro perde granularidade e precisão.
✅ Sobreposição entre chunks evita perder contexto cortado na fronteira.
✅ Chunking por estrutura (parágrafos/seções) preserva unidades de sentido melhor que tamanho fixo.
✅ O tamanho ideal do chunk depende do tipo de documento e das perguntas — teste e compare.
