# 8.1 — Quando NÃO Usar IA

> Nem todo problema se beneficia de um LLM. Usar IA onde uma solução determinística,
> mais simples ou mais confiável resolveria melhor é um erro de engenharia tão real
> quanto qualquer outro.

## Sinais de que IA generativa é a ferramenta errada

| Sinal | Por quê | Alternativa melhor |
|---|---|---|
| A tarefa tem uma resposta exata e computável | LLM pode "aproximar" em vez de calcular exatamente | Código determinístico (matemática, regras de negócio) |
| Precisão de 100% é obrigatória, sem margem para erro | LLMs alucinam (módulo 1.3) — nunca há garantia total | Validação programática, regras explícitas |
| A decisão tem consequências legais, médicas ou de segurança significativas | Erro de um LLM nessas áreas pode ser grave e difícil de auditar | Sistema especializado + revisão humana obrigatória |
| O problema é simples e já resolvido por uma ferramenta determinística | Adicionar IA só aumenta custo, latência e superfície de erro | `regex`, validação de schema, lógica condicional simples |
| Você precisa de reprodutibilidade exata entre execuções | LLMs são probabilísticos por natureza (módulo 1.1) | Função determinística |

## Exemplos concretos

```
❌ Usar um LLM para validar se um CPF é matematicamente válido.
✅ Usar um algoritmo determinístico (o cálculo do dígito verificador é bem definido).

❌ Usar um LLM para somar valores de uma planilha financeira.
✅ Usar código que soma os números — sem risco de "aproximação".

❌ Usar um LLM sozinho para decidir se um empréstimo deve ser aprovado.
✅ Usar regras de negócio auditáveis, com IA no máximo como apoio a um analista humano
   que toma a decisão final.
```

## O critério prático

Pergunte: **"Essa tarefa exige compreensão de linguagem natural, julgamento
contextual ou geração de conteúdo — coisas em que um LLM é bom — ou é fundamentalmente
um cálculo, uma regra fixa, ou uma decisão de alto risco?"**

Se for a segunda opção, considere seriamente não usar um LLM, ou usá-lo apenas como uma
peça (ex: extrair dados de um texto livre) dentro de um sistema maior que tem validação
determinística ao redor.

## IA como parte de um sistema, não o sistema inteiro

Na prática, a resposta raramente é "IA sim" ou "IA não" de forma binária — é sobre
**onde** colocar a fronteira. Um sistema de aprovação de crédito pode usar um LLM para
extrair e resumir informações de documentos (tarefa de linguagem, onde IA é boa), mas a
decisão final de aprovação deve vir de regras de negócio explícitas e auditáveis, não do
julgamento do LLM.

## Pontos-Chave

✅ Tarefas com resposta exata e computável não devem depender de um LLM (que aproxima, não calcula).
✅ Decisões de alto risco (legal, médico, financeiro) exigem revisão humana, não IA sozinha.
✅ Adicionar IA a um problema já resolvido por uma ferramenta determinística só aumenta risco e custo.
✅ Na prática, o mais comum é usar IA como uma peça de um sistema maior, com validação ao redor — não como decisor único.
