# 8.4 — Revisão Humana e Responsabilidade

> **Human-in-the-loop**: projetar o sistema para que um humano revise ou aprove decisões
> antes que elas tenham efeito, especialmente em casos de alto risco ou baixa confiança do
> modelo.

## A responsabilidade não desaparece porque uma IA tomou a decisão

Se um sistema com IA toma uma decisão errada — nega um reembolso legítimo, aprova um
empréstimo que não deveria, envia uma mensagem inadequada a um cliente — a responsabilidade
é de quem construiu e operou o sistema, não do modelo. "A IA decidiu" não é uma defesa
válida, nem tecnicamente nem eticamente. Isso conecta diretamente com o módulo 6.3
(permissions): a mesma lógica de "o que pode rodar automaticamente vs. o que precisa de
aprovação" se aplica aqui, só que para decisões de negócio, não só ações técnicas.

## Quando exigir revisão humana

| Critério | Exemplo |
|---|---|
| Alto impacto se errado | Decisões financeiras, legais, médicas, de contratação |
| Baixa confiança do próprio modelo | O modelo mesmo sinaliza incerteza, ou respostas são inconsistentes entre execuções |
| Categoria sensível conhecida | Reclamações jurídicas, dados de saúde, denúncias |
| Ação irreversível | Deletar dados, enviar comunicação pública, processar pagamento |
| Primeira vez que o sistema lida com um tipo de caso | Falta de histórico de acerto para esse padrão específico |

## Exemplo em Python — roteamento por confiança e categoria

Um padrão comum: pedir ao próprio modelo que classifique sua confiança na resposta, e usar
isso (combinado com a categoria da tarefa) para decidir se um humano precisa revisar antes
de qualquer ação ser tomada.

Código completo: [`exemplos-python/8.4_roteamento_para_revisao_humana.py`](exemplos-python/8.4_roteamento_para_revisao_humana.py)

```python
def processar_ticket(texto_ticket: str, limiar_confianca: float = 0.8) -> dict:
    classificacao = classificar_ticket(texto_ticket)

    precisa_revisao_humana = (
        classificacao["categoria"] in CATEGORIAS_SEMPRE_REVISADAS
        or classificacao["confianca"] < limiar_confianca
    )

    return {**classificacao, "acao": "enviar_para_revisao_humana" if precisa_revisao_humana
                                       else "responder_automaticamente"}
```

Note que a confiança **autorrelatada pelo modelo** é um sinal útil, mas não perfeito — um
modelo pode estar confiante e errado ao mesmo tempo (isso é literalmente o que é uma
alucinação, módulo 1.3). Combine confiança com regras explícitas de categoria (como
`CATEGORIAS_SEMPRE_REVISADAS`) para os casos onde o risco justifica revisão humana
independente da confiança relatada.

## Auditoria: manter rastro do que a IA decidiu

Além da revisão antes da ação, vale manter um **log auditável** de toda decisão tomada por
um sistema com IA — o que foi decidido, com que informação, e (se aplicável) se um humano
revisou. Isso permite investigar problemas depois e é frequentemente uma exigência
regulatória em setores como financeiro e saúde.

## Resumo do módulo: uma checklist de uso responsável

- [ ] Avaliei se essa tarefa realmente se beneficia de IA (aula 8.1)?
- [ ] Testei o sistema para viés e inconsistência antes de confiar nele (aula 8.2)?
- [ ] Removi/mascarei dados sensíveis antes de enviar a uma API externa (aula 8.3)?
- [ ] Defini claramente quais decisões exigem revisão humana antes de terem efeito (aula 8.4)?
- [ ] Existe um log auditável das decisões tomadas pelo sistema?

## Pontos-Chave

✅ A responsabilidade por decisões erradas é de quem construiu o sistema, não do modelo.
✅ Alto impacto, baixa confiança, categoria sensível e ações irreversíveis são gatilhos para revisão humana.
✅ Confiança autorrelatada pelo modelo é útil mas imperfeita — combine com regras explícitas de categoria.
✅ Manter um log auditável das decisões é essencial para investigação e, em muitos setores, exigência regulatória.
