# 8.2 — Vieses e Alucinações

> **Viés**: quando um modelo trata grupos ou atributos diferentes de forma sistematicamente
> desigual, sem justificativa relacionada à tarefa — geralmente refletindo padrões
> presentes nos dados de treinamento.

## Recapitulando alucinação (módulo 1.3), sob a lente de uso responsável

Já vimos que alucinação é uma consequência de como um LLM gera texto, não um "bug raro"
(módulo 1.3). No contexto de uso responsável, o ponto central é: **você é responsável por
mitigar isso na sua aplicação**, não pode assumir que o modelo vai se autocorrigir.

## De onde vem o viés

LLMs são treinados em grandes volumes de texto produzido por humanos — e esse texto carrega
os vieses presentes na sociedade e nas fontes usadas no treinamento. Isso pode se manifestar
como: associações estereotipadas entre nomes/grupos e características, tom diferente ao
avaliar a mesma situação com atributos demográficos diferentes, ou respostas que refletem
uma perspectiva cultural dominante como se fosse universal.

## Por que isso importa na prática

Um sistema que usa IA para **triagem de currículos**, **avaliação de crédito**, ou
**moderação de conteúdo** pode reproduzir ou até amplificar vieses existentes, com
consequências reais para pessoas — e, dependendo do contexto e jurisdição, consequências
legais para quem opera o sistema.

## Testando por consistência e por viés

Duas técnicas simples de auditoria antes de confiar em um sistema baseado em LLM para
decisões sensíveis:

Código completo: [`exemplos-python/8.2_teste_de_consistencia_entre_variacoes.py`](exemplos-python/8.2_teste_de_consistencia_entre_variacoes.py)

```python
def teste_de_consistencia(pergunta: str, n_execucoes: int = 3) -> list[str]:
    """Respostas muito diferentes entre execuções são sinal de possível alucinação."""
    return [perguntar(pergunta) for _ in range(n_execucoes)]

def teste_de_vies_por_atributo(template: str, valores_para_testar: list[str]) -> dict[str, str]:
    """Roda o mesmo prompt trocando só um atributo — compara se o resultado muda
    de forma não justificável."""
    return {valor: perguntar(template.format(atributo=valor)) for valor in valores_para_testar}
```

Nenhuma das duas técnicas é uma prova definitiva — são sinais que indicam onde investigar
mais a fundo antes de confiar no sistema para decisões que afetam pessoas.

## Mitigações práticas

| Problema | Mitigação |
|---|---|
| Alucinação | RAG para ancorar em fontes reais (módulo 3), `temperature` baixa, pedir a fonte |
| Viés em decisões sobre pessoas | Auditoria com variação de atributos, revisão humana obrigatória, nunca decisor único |
| Inconsistência entre execuções | Rodar múltiplas vezes para tarefas críticas, usar `temperature=0` quando aplicável |
| Viés não detectado a tempo | Testes de fairness como parte do processo de desenvolvimento, não só ao final |

## Pontos-Chave

✅ Alucinação e viés são riscos estruturais do LLM — mitigar é responsabilidade de quem constrói a aplicação.
✅ Viés reflete padrões presentes nos dados de treinamento e pode se manifestar como tratamento desigual entre grupos.
✅ Testar variando um único atributo no mesmo prompt é uma forma simples de detectar viés sistemático.
✅ Sistemas que afetam pessoas (crédito, contratação, moderação) exigem auditoria e revisão humana — nunca IA como decisor único.
