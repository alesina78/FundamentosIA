# 9.1 — IA no Design e Planejamento

> A primeira etapa em que IA agrega valor no fluxo de desenvolvimento não é escrever
> código — é ajudar a **estruturar o pensamento** antes de qualquer linha ser escrita.

## Onde a IA ajuda antes do código

| Etapa | Como a IA ajuda |
|---|---|
| Transformar uma ideia vaga em algo estruturado | Gerar um rascunho de RFC/design doc a partir de uma descrição informal |
| Explorar alternativas | Pedir 2-3 abordagens diferentes com trade-offs, em vez de só uma |
| Identificar lacunas | Perguntar "o que está faltando decidir aqui?" antes de começar a implementar |
| Escrever a especificação | Transformar decisões já tomadas em uma spec clara (módulo 6) |

Isso conecta diretamente com o módulo 6 (SDD): o design/planejamento é onde a spec nasce —
quanto melhor essa etapa, menos retrabalho na implementação.

## Exemplo em Python — de ideia informal a rascunho de RFC

Código completo: [`exemplos-python/9.1_gerar_rascunho_de_rfc.py`](exemplos-python/9.1_gerar_rascunho_de_rfc.py)

```python
prompt = f"""\
Você é um engenheiro de software sênior ajudando a estruturar uma ideia em um rascunho
de RFC (design doc) para revisão do time. Use este formato:

## Problema
## Objetivo (o que resolve, especificamente)
## Não-objetivos (o que fica de fora dessa proposta)
## Proposta (2-3 abordagens possíveis, com trade-offs)
## Perguntas em aberto (o que precisa ser decidido pelo time antes de prosseguir)

Ideia informal do autor:
{ideia}
"""
```

Note a instrução explícita para **sinalizar perguntas em aberto** em vez de o modelo
presumir respostas — isso é crítico: o papel da IA aqui é ajudar a organizar o pensamento
e apontar o que falta decidir, não tomar as decisões de arquitetura no lugar do time.

## O que a IA não deve decidir sozinha nessa etapa

- Trade-offs que envolvem contexto organizacional (orçamento, prazo, prioridades do negócio) que o modelo não tem acesso.
- Decisões que exigem conhecimento tácito do sistema existente (débito técnico conhecido, decisões históricas do time).
- A escolha final entre alternativas — a IA pode listar opções e trade-offs, mas a decisão é do time.

## O ciclo: ideia → design → spec

```
Ideia informal (humano)
        │
        ▼
Rascunho de design/RFC estruturado (IA ajuda a organizar)
        │
        ▼
Discussão e decisão do time (humano)
        │
        ▼
Spec clara e testável (módulo 6.2) — pronta para implementação
```

## Pontos-Chave

✅ IA ajuda a transformar ideias vagas em documentos estruturados para discussão, não substitui a decisão do time.
✅ Pedir múltiplas abordagens com trade-offs evita ancorar numa única solução prematuramente.
✅ Sinalizar "perguntas em aberto" explicitamente evita que o modelo presuma decisões que cabem ao time.
✅ O design bem feito é a base de uma spec clara (módulo 6), que por sua vez reduz retrabalho na implementação.
