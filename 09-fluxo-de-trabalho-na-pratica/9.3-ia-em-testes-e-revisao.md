# 9.3 — IA em Testes e Revisão de Código

> Gerar testes com IA é útil — mas o valor real só aparece quando os testes gerados são
> **executados de verdade**, não apenas lidos e aceitos por confiança.

## Por que rodar os testes de verdade importa

Na aula 6.3 vimos que pedir para o modelo "verificar mentalmente" se um código passa nos
casos de teste é útil como triagem rápida, mas não substitui execução real. O mesmo vale
aqui, ao contrário: **gerar** testes com IA é ótimo para acelerar a cobertura, mas os
testes gerados precisam **rodar de verdade** contra o código — inclusive porque o próprio
modelo pode gerar um teste com uma asserção incorreta.

## Exemplo em Python — gerar testes e executá-los de verdade

Código completo: [`exemplos-python/9.3_gerar_e_rodar_testes.py`](exemplos-python/9.3_gerar_e_rodar_testes.py)

```python
def gerar_testes(codigo: str) -> str:
    prompt = f"""\
Escreva testes usando pytest para a função abaixo. Cubra: caso normal, valores limite,
e os casos de erro.

```python
{codigo}
```

Responda APENAS com o código dos testes, sem explicação.
"""
    ...

def rodar_testes_gerados(codigo_fonte: str, codigo_testes: str) -> None:
    # escreve os arquivos numa pasta temporária e roda `pytest` de verdade
    resultado = subprocess.run(["python", "-m", "pytest", "-v", ...], capture_output=True, text=True)
    print(resultado.stdout)
    if resultado.returncode != 0:
        print("--- Testes falharam — revisar antes de aceitar a implementação ---")
```

Note que o script **realmente executa** `pytest` via `subprocess` — o resultado não é uma
opinião do modelo sobre se os testes passariam, é o resultado real de rodá-los.

## IA como apoio ao code review

Além de gerar testes, IA pode ser útil como uma **primeira passada** de revisão de código —
apontar bugs potenciais, código não idiomático, ou casos de borda não tratados — antes da
revisão humana. Um ponto importante ao usar IA para revisão: peça para reportar **tudo** que
encontrar, mesmo de baixa severidade ou incerto, e filtre a importância depois — modelos
tendem a seguir literalmente instruções como "só reporte problemas importantes", o que pode
fazer com que bugs reais passem despercebidos por serem julgados "não importantes o
suficiente" antes mesmo de chegarem até você.

```
❌ "Revise este código e aponte só os problemas mais importantes."
✅ "Revise este código e liste TODOS os problemas encontrados, incluindo os que você não
   tem certeza. Para cada um, indique a severidade estimada — eu decido o que priorizar."
```

## O papel da IA vs. o papel do humano em testes e revisão

| Etapa | Papel da IA | Papel do humano |
|---|---|---|
| Gerar casos de teste | Sugerir cobertura ampla rapidamente | Confirmar que os casos fazem sentido para o domínio |
| Rodar os testes | — (é execução determinística, não julgamento) | Interpretar falhas e decidir o que fazer |
| Revisão de código | Primeira passada, listar tudo que encontrar | Julgar severidade, priorizar, decidir o que corrigir |
| Aprovação final | — | Sempre humana, especialmente em produção |

## Pontos-Chave

✅ Testes gerados por IA precisam ser executados de verdade — não apenas lidos e aceitos.
✅ IA acelera a criação de cobertura de testes, mas não substitui a validação real da execução.
✅ Em revisão de código, peça para listar tudo, não filtrar por "importância" — filtrar é seu trabalho, não do modelo.
✅ A aprovação final de qualquer mudança em produção continua sendo uma decisão humana.
