# 5.2 — Criando um Servidor MCP Simples em Python

> O SDK oficial Python do MCP oferece o **FastMCP**, uma forma de expor funções Python
> como ferramentas MCP usando decorators — sem precisar implementar o protocolo na mão.

## Setup

```bash
pip install "mcp[cli]"
```

## Anatomia de um servidor MCP com FastMCP

Código completo: [`exemplos-python/5.2_servidor_mcp_simples.py`](exemplos-python/5.2_servidor_mcp_simples.py)

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("Servidor de Pedidos")

@mcp.tool()
def consultar_status_pedido(numero_pedido: str) -> dict:
    """Consulta o status de um pedido pelo número.

    Args:
        numero_pedido: o número identificador do pedido, ex: "1001".
    """
    pedido = PEDIDOS.get(numero_pedido)
    if pedido is None:
        return {"erro": f"Pedido {numero_pedido} não encontrado."}
    return pedido

if __name__ == "__main__":
    mcp.run()
```

Note como o decorator `@mcp.tool()` transforma a função Python numa ferramenta MCP
automaticamente — o **docstring** vira a descrição que o modelo usa para decidir quando
chamar (exatamente como o campo `description` do tool use manual, aula 4.1), e a
**assinatura da função** (tipos dos parâmetros) vira o schema de entrada.

## Tools vs. Resources

O exemplo também mostra um **resource** — dado somente-leitura, sem efeitos colaterais,
identificado por uma URI:

```python
@mcp.resource("pedidos://lista")
def listar_todos_pedidos() -> str:
    """Recurso somente-leitura: lista todos os pedidos cadastrados."""
    ...
```

Use **tools** quando a ação tem efeito (consultar algo específico, ou pior, modificar
algo). Use **resources** para dados que o cliente pode simplesmente "ler" e anexar ao
contexto, sem uma chamada de função explícita do modelo.

## Prompts: o terceiro primitivo

Um servidor MCP também pode expor **prompts** — templates de instrução prontos, escritos
por quem conhece o domínio, que o usuário aciona quando quer:

```python
@mcp.prompt()
def resumo_para_cliente(numero_pedido: str) -> str:
    """Prompt pronto: gera uma mensagem de atualização para enviar ao cliente."""
    return (
        f"Consulte o pedido {numero_pedido} e escreva uma mensagem curta e cordial "
        "para o cliente informando a situação atual. Em português, no máximo 3 frases. "
        "Se o pedido estiver atrasado, reconheça o atraso antes de dar a nova previsão."
    )
```

Repare que a função apenas **devolve um texto** — ela não chama o modelo nem consulta os
pedidos. O que ela produz é a mensagem que será colocada na conversa como se o usuário a
tivesse digitado; a partir daí o modelo é quem decide chamar `consultar_status_pedido`.

A diferença essencial em relação aos outros dois primitivos está em **quem aciona**:

| Primitivo | Quem decide usar |
|---|---|
| **Tool** | O modelo, no meio do raciocínio |
| **Resource** | A aplicação (host), que anexa o dado ao contexto |
| **Prompt** | O usuário, explicitamente |

No Claude Code, prompts de servidores MCP viram slash commands no formato
`/mcp__<servidor>__<prompt>` — o deste exemplo apareceria como
`/mcp__pedidos__resumo_para_cliente`. É o mecanismo para empacotar aquele prompt bom que
alguém do time refinou e que hoje vive num arquivo de texto que ninguém acha.

## Rodando e testando o servidor

O SDK do MCP inclui um inspetor interativo para testar seu servidor sem precisar conectar
a um cliente de verdade:

```bash
mcp dev 5.2_servidor_mcp_simples.py
```

Isso abre uma interface web onde você pode chamar `consultar_status_pedido` manualmente e
ver a resposta — útil para depurar antes de conectar a um cliente real (Claude Desktop,
Claude Code, ou sua própria aplicação).

> ⚠️ **Pré-requisito escondido: Node.js.** O `mcp dev` chama `npx @modelcontextprotocol/inspector`
> por baixo — o inspetor é um pacote Node, não Python. Sem Node/npm instalado o comando
> falha com "npx não encontrado". Se for o seu caso, instale pelo site oficial:
> [nodejs.org/download](https://nodejs.org/en/download) (a versão **LTS** basta; o `npx`
> vem junto). Isso vale **só para o inspetor**: o servidor em si é Python puro e conecta a
> um client de verdade sem precisar de Node. A primeira execução demora mais porque o
> `npx` baixa o inspetor na hora.

## Transporte: como client e server se comunicam

| Transporte | Quando usar |
|---|---|
| **stdio** | Servidor local, rodando como subprocesso do client — mais comum para uso pessoal/dev |
| **HTTP (Streamable HTTP)** | Servidor remoto, acessível por URL — necessário quando client e server não estão na mesma máquina |

O exemplo acima usa `mcp.run()`, que por padrão usa stdio — ideal para rodar localmente e
conectar via Claude Desktop ou Claude Code, apontando a configuração do client para o
caminho deste arquivo.

## Instalando o servidor no Claude Code

Testado no inspetor, o próximo passo é registrar o servidor num client de verdade. No
Claude Code isso é um comando:

> ℹ️ **Pré-requisito: o Claude Code instalado.** Os comandos `claude` desta seção vêm da
> CLI do Claude Code — veja a
> [documentação oficial de instalação](https://docs.claude.com/en/docs/claude-code/setup).
> Se você preferir usar o **Claude Desktop** como client, pule para a subseção
> *Alternativa sem CLI*, no fim desta seção: lá a configuração é feita editando um arquivo
> JSON, sem CLI nenhuma.

```bash
claude mcp add pedidos -- python C:\caminho\absoluto\5.2_servidor_mcp_simples.py
```

O `--` separa os argumentos do `claude` do comando que sobe o servidor. Use caminho
**absoluto** para o script: o Claude Code executa o servidor como subprocesso, e o diretório
de trabalho dele não é necessariamente o seu — caminho relativo é a causa mais comum de
"servidor não conecta". Para passar variáveis de ambiente (um token, uma URL de banco), use
`--env CHAVE=valor` antes do `--`.

> 💡 **Usando venv?** Ative o ambiente **antes** de rodar o `claude mcp add`. O `python` é
> resolvido no momento do registro, e o caminho do interpretador do venv fica gravado na
> configuração — você pode conferir com `claude mcp list`, que mostra algo como
> `.venv\Scripts\python.exe`. Não é preciso escrever o caminho do interpretador à mão.
> Instale as dependências (`pip install "mcp[cli]"`) dentro do venv antes disso, senão o
> servidor sobe e morre com `ModuleNotFoundError`.

As outras duas formas que você vai encontrar:

```bash
# Servidor remoto, acessível por URL
claude mcp add --transport http nome https://exemplo.com/mcp

# Servidor publicado em npm/PyPI — como a maioria dos servidores oficiais é distribuída
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem C:\meu\projeto
```

### Escopo: quem enxerga o servidor

| `--scope` | Onde a configuração é gravada | Quando usar |
|---|---|---|
| `local` (padrão) | configuração sua, só neste projeto | testando algo |
| `project` | arquivo `.mcp.json`, versionado no repositório | o time todo precisa do servidor |
| `user` | sua configuração global | você usa em todos os projetos |

O escopo `project` é o que torna um servidor MCP parte do projeto: o `.mcp.json` entra no
git e quem clonar o repositório já recebe o servidor configurado.

> ⚠️ **O escopo `local` fica amarrado à pasta onde você rodou o comando.** É a origem de um
> sintoma que confunde muita gente: o servidor aparece conectado no `claude mcp list` do
> terminal, mas **some na extensão do VS Code** — ou em qualquer outra sessão. Não é bug: a
> extensão abriu uma pasta diferente daquela onde o registro foi feito, e naquele contexto o
> servidor simplesmente não existe. Registrar de dentro de uma subpasta do projeto (como
> `exemplos-python/`) cria um registro separado do da raiz, e é fácil acabar com o mesmo
> servidor cadastrado duas vezes sem perceber. Se quiser o servidor disponível em qualquer
> lugar, use `--scope user`; se quiser em qualquer sessão deste repositório, `--scope project`
> a partir da **raiz**.

### Conferindo

`claude mcp list` no terminal, ou `/mcp` dentro da sessão, mostram o status da conexão e as
ferramentas expostas. Se aparecer como *failed*, `claude mcp get <nome>` mostra o comando
exato que está sendo executado — normalmente o erro de caminho salta aos olhos ali.

Depois de adicionar um servidor com o VS Code já aberto, **recarregue a janela**
(`Ctrl+Shift+P` → *Reload Window*): a extensão lê a configuração de MCP na inicialização.

### Quando a conexão falha

O erro mais comum é genérico e pouco informativo:

```
✘ Failed to connect — -32000: MCP error -32000
```

O `-32000` é o código do JSON-RPC para "a conexão morreu", e aparece igual para caminho
errado, dependência faltando, erro de sintaxe no arquivo ou variável de ambiente ausente.
Para ver a causa real, rode o servidor direto no terminal:

```bash
python 5.2_servidor_mcp_simples.py
```

Ele deve ficar **parado**, sem imprimir nada e sem devolver o prompt — é o comportamento
esperado de um servidor stdio esperando o client (`Ctrl+C` para sair). Se em vez disso
aparecer um traceback, o problema está no servidor ou no ambiente, não no registro.

| Sintoma | Causa provável |
|---|---|
| `ModuleNotFoundError: No module named 'mcp'` | Faltou `pip install "mcp[cli]"` — ou instalou fora do venv que você ativou |
| Falha só pelo client, mas roda no terminal | Caminho relativo no registro, ou venv não estava ativo no `claude mcp add` |
| `FileNotFoundError` no caminho do script | Copiou `C:\caminho\absoluto\...` literalmente do exemplo |

### Alternativa sem CLI: Claude Desktop

No Claude Desktop não há comando — você declara o servidor no arquivo
`claude_desktop_config.json` (acessível por *Settings → Developer → Edit Config*) e
reinicia o aplicativo:

```json
{
  "mcpServers": {
    "pedidos": {
      "command": "python",
      "args": ["C:\\caminho\\absoluto\\5.2_servidor_mcp_simples.py"],
      "env": { "MINHA_VARIAVEL": "valor" }
    }
  }
}
```

É a mesma informação que o `claude mcp add` grava — comando, argumentos e variáveis de
ambiente — só que escrita à mão. Note as barras invertidas duplicadas: em JSON, `\` precisa
ser escapado.

## Pontos-Chave

✅ `@mcp.tool()` transforma uma função Python numa ferramenta MCP — docstring vira descrição, assinatura vira schema.
✅ Tools são para ações; resources são para dados somente-leitura identificados por URI.
✅ Prompts são templates acionados pelo usuário — no Claude Code viram slash commands `/mcp__servidor__prompt`.
✅ `mcp dev` abre um inspetor interativo para testar o servidor sem precisar de um cliente real — ele exige Node.js, mas o servidor não.
✅ stdio é o transporte padrão para servidores locais; HTTP é necessário para servidores remotos.
✅ `claude mcp add nome -- python /caminho/absoluto.py` registra o servidor no Claude Code; caminho relativo é a causa mais comum de falha.
✅ `--scope project` grava em `.mcp.json` e versiona o servidor junto com o repositório.
✅ O escopo `local` vale só na pasta onde você registrou — daí o servidor aparecer no `claude mcp list` e sumir na extensão do VS Code.
✅ Com venv, ative o ambiente antes do `claude mcp add`: o interpretador é resolvido e gravado no registro.
✅ `-32000` é um erro genérico de conexão — rode o servidor direto no terminal para ver a causa real.
