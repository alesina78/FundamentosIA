# 5.3 — Quando e Como Integrar MCP nos Seus Workflows

> Nem toda integração precisa ser um servidor MCP — a decisão depende de quantos clientes
> vão reutilizar essa integração e se ela precisa ser mantida por fora da sua aplicação.

## MCP vs. tool use direto: quando usar cada um

| Situação | Abordagem recomendada |
|---|---|
| Ferramenta usada só pela sua aplicação, uma vez | Tool use direto (aula 4.1) — mais simples |
| Ferramenta que vários assistentes/apps vão reutilizar | Servidor MCP — escreva uma vez, reutilize em vários hosts |
| Integração com uma ferramenta de terceiros que já tem servidor MCP pronto | Conectar ao servidor MCP existente (GitHub, Slack, etc. já têm servidores MCP oficiais) |
| Você quer que usuários do Claude Desktop/Claude Code também usem essa ferramenta | Servidor MCP — esses hosts já sabem "falar" MCP nativamente |
| Protótipo rápido, uma função simples, sem reuso previsto | Tool use direto |

Regra prática: se você está implementando tool use manualmente (aula 4.1) e percebe que
está reescrevendo a mesma integração em mais de um lugar (ou mais de uma aplicação), é
sinal de que vale a pena extrair para um servidor MCP.

## Antes de construir, procure

Na aula 5.2 você escreveu um servidor do zero para entender o mecanismo. No dia a dia, a
primeira pergunta é outra: **alguém já escreveu esse servidor?** Existem catálogos que
reúnem servidores MCP publicados:

- [mcpservers.org](https://mcpservers.org/pt-BR/) — catálogo navegável por categoria, com
  instruções de instalação prontas para cada servidor (disponível em português)
- [`modelcontextprotocol/servers`](https://github.com/modelcontextprotocol/servers) — o
  repositório oficial, com os servidores de referência mantidos pelo projeto

Ao avaliar um servidor do catálogo, três perguntas importam mais que a lista de recursos:
**quem mantém** (projeto oficial, empresa, ou uma pessoa sozinha?), **que credenciais ele
pede** (nenhuma? um token? sua sessão de login?) e **se ele escreve ou apenas lê**. Um
servidor que só lê e não pede credencial é um risco muito diferente de um que envia
mensagens na sua conta.

## Exemplo: o servidor MCP de Excel

Um bom caso para entender *por que* servidores MCP existem é o
[Excel MCP Server](https://mcpservers.org/pt-BR/servers/negokaz/excel-mcp-server):

```bash
claude mcp add --scope user excel -- npx -y @negokaz/excel-mcp-server
```

Sem credenciais, sem conta — precisa apenas de Node 20+. Depois de conectar, o modelo passa
a ter ferramentas como `excel_describe_sheets`, `excel_read_sheet` e `excel_write_to_sheet`.

### Por que a IA é ruim com Excel sem isso

Um `.csv` é texto puro: o modelo simplesmente lê o conteúdo do arquivo e entende. Um
`.xlsx` **não é um arquivo de texto** — é um pacote ZIP contendo vários XMLs comprimidos,
com o conteúdo espalhado entre eles. Sem uma ferramenta que abra e interprete esse formato,
não há o que "ler": o modelo recebe bytes binários, ou nada.

E mesmo resolvido o formato, uma planilha carrega coisas que texto plano não representa:

| O que existe na planilha | O que se perde sem uma ferramenta adequada |
|---|---|
| Várias abas | Qual aba? Um CSV é uma tabela só |
| Fórmulas (`=SOMA(B2:B10)`) | O modelo vê o resultado ou a fórmula? São perguntas diferentes |
| Células mescladas, cabeçalhos em duas linhas | A "tabela" não começa em A1, e a leitura ingênua desalinha tudo |
| Formatação, cores, validação de dados | Muitas vezes é onde mora a informação (status por cor, por exemplo) |
| Planilhas com centenas de milhares de células | Não cabem no contexto — é preciso paginar |

O servidor MCP resolve os dois problemas de uma vez: ele **abre o formato** e **devolve só
o pedaço pedido**, já estruturado (por isso ele tem um limite de células por página). É o
mesmo raciocínio da aula 5.2 — a ferramenta faz o trabalho determinístico, e o modelo faz
o trabalho de interpretação.

> ⚠️ Repare que esse servidor **escreve** nos seus arquivos (`excel_write_to_sheet`,
> `excel_format_range`). Diferente de um servidor somente-leitura, aqui um erro do modelo
> altera um arquivo de verdade. Teste com uma cópia descartável — e note que essa distinção
> entre ler e agir é o assunto do módulo 8.

## Duas formas de conectar ao MCP no seu código

**1. Client MCP local** (SDK do MCP) — você mesmo gerencia a conexão com o servidor,
geralmente via stdio (servidor rodando localmente). Dá mais controle, mas mais código.

**2. MCP Connector da API da Anthropic** (beta) — a própria API da Anthropic se conecta a
um servidor MCP remoto por você; você só declara a URL do servidor na chamada.

Código completo: [`exemplos-python/5.3_conectando_servidor_mcp_remoto.py`](exemplos-python/5.3_conectando_servidor_mcp_remoto.py)

```python
response = client.beta.messages.create(
    model="claude-haiku-4-5",
    max_tokens=500,
    betas=["mcp-client-2025-11-20"],
    mcp_servers=[
        {"type": "url", "url": "https://exemplo-servidor-mcp.com/sse", "name": "servidor-de-pedidos"}
    ],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "servidor-de-pedidos"}],
    messages=[{"role": "user", "content": "Qual o status do pedido 1001?"}],
)
```

Isso é útil quando o servidor MCP já é remoto (hospedado por você ou por terceiros) e você
quer que a API do Claude se conecte diretamente, sem seu código precisar ser o "meio de
campo" entre client e server.

## Onde MCP se encaixa no fluxo de desenvolvimento com IA

MCP é especialmente relevante quando você usa **harness de agentic coding** (módulo 6,
como Claude Code): esses harnesses já falam MCP nativamente, então dar a um agente de
código acesso ao seu banco de dados, sistema de tickets, ou API interna via um servidor MCP
é a forma padronizada de estender o que o agente consegue fazer — sem precisar modificar o
harness em si.

## Checklist antes de construir um servidor MCP

- [ ] Existe um servidor MCP oficial/da comunidade para esse sistema? (verifique antes de reinventar)
- [ ] Mais de uma aplicação/host vai se beneficiar dessa integração?
- [ ] A integração precisa ser mantida e versionada separadamente da aplicação principal?
- [ ] O sistema alvo tem autenticação que precisa ser tratada (tokens, OAuth)?

Se a resposta para as duas primeiras perguntas for "sim", construir um servidor MCP
provavelmente compensa o esforço extra em relação a tool use direto.

## Pontos-Chave

✅ Tool use direto é mais simples para uso único; MCP compensa quando há reuso entre aplicações/hosts.
✅ Verifique se já existe um servidor MCP pronto para o sistema antes de construir um novo — comece pelos catálogos (mcpservers.org, `modelcontextprotocol/servers`).
✅ Ao escolher um servidor de terceiros, avalie quem mantém, que credenciais pede e se ele escreve ou apenas lê.
✅ Formatos binários como `.xlsx` (um ZIP de XMLs, ao contrário do CSV) são inacessíveis ao modelo sem uma ferramenta que os abra — é um caso exemplar de para que servem os servidores MCP.
✅ O MCP Connector da API permite conectar a servidores remotos sem gerenciar o client você mesmo.
✅ Harnesses de agentic coding (módulo 6) já falam MCP nativamente — é a forma padrão de estendê-los.
