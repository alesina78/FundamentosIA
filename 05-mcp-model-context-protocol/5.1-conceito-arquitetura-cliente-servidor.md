# 5.1 — Conceito e Arquitetura Cliente-Servidor

> **MCP (Model Context Protocol)**: um protocolo aberto, criado pela Anthropic, que
> padroniza como aplicações de IA se conectam a fontes de dados e ferramentas externas —
> um "USB-C para integrações de IA".

## O problema que o MCP resolve

Antes do MCP, cada combinação de "assistente de IA X precisa acessar sistema Y" exigia uma
integração específica, escrita do zero. Se você tinha 5 assistentes de IA e 10 sistemas
diferentes (GitHub, Slack, banco de dados, CRM...), podia acabar com até 50 integrações
distintas para manter.

```
Sem MCP:                          Com MCP:

Assistente A ─┬─ GitHub           Assistente A ─┐
Assistente B ─┼─ Slack            Assistente B ─┼─ MCP ─┬─ GitHub
Assistente C ─┴─ Banco de dados   Assistente C ─┘       ├─ Slack
(N x M integrações)                                      └─ Banco de dados
                                   (servidor MCP escrito uma vez, usado por qualquer cliente)
```

Um servidor MCP para o GitHub, por exemplo, escrito uma única vez, pode ser usado por
qualquer aplicação de IA compatível com MCP — não só pela Anthropic.

## Arquitetura: Host, Client e Server

| Componente | Papel |
|---|---|
| **Host** | A aplicação que o usuário usa (ex: Claude Desktop, Claude Code, seu próprio app) |
| **Client MCP** | Vive dentro do host; mantém uma conexão 1-para-1 com um servidor MCP |
| **Server MCP** | Processo separado que expõe ferramentas, dados ou prompts sobre um sistema específico (ex: GitHub, banco de dados, sistema de arquivos) |

```
┌─────────────────────────────┐
│           Host              │
│  (Claude Desktop, seu app)  │
│                              │
│   ┌────────┐   ┌────────┐   │
│   │Client 1│   │Client 2│   │
│   └───┬────┘   └───┬────┘   │
└───────┼─────────────┼───────┘
        │             │
   ┌────▼────┐   ┌────▼────┐
   │Server MCP│   │Server MCP│
   │ (GitHub) │   │ (Slack)  │
   └─────────┘   └─────────┘
```

Um host pode manter conexões simultâneas com vários servidores MCP, cada conexão isolada
através de um client dedicado.

## O que um servidor MCP pode expor

| Primitivo | O que é | Análogo a |
|---|---|---|
| **Tools** | Funções que o modelo pode chamar (com efeitos colaterais) | Tool use (aula 4.1) |
| **Resources** | Dados que podem ser lidos e injetados como contexto | Um arquivo, uma linha de banco de dados |
| **Prompts** | Templates de prompt reutilizáveis, definidos pelo servidor | Um "prompt salvo" pronto para usar |

Na prática, a maioria dos servidores MCP usados no dia a dia expõe principalmente
**tools** — é conceitualmente muito parecido com o tool use da aula 4.1, mas com um
protocolo padronizado para descoberta e comunicação em vez de você definir cada ferramenta
manualmente em cada aplicação.

## MCP não substitui tool use — ele o padroniza

MCP não é uma tecnologia concorrente ao tool use — é uma camada de padronização sobre ele.
Ao conectar seu host a um servidor MCP, as ferramentas expostas pelo servidor aparecem para
o modelo exatamente como ferramentas de tool use normais — só que você não precisou
escrever o código de cada uma; o servidor já cuida disso.

## Pontos-Chave

✅ MCP padroniza a conexão entre assistentes de IA e sistemas externos — evita reescrever integrações N vezes.
✅ Arquitetura: Host (app) → Client (conexão 1-para-1) → Server (expõe tools/resources/prompts).
✅ Um servidor MCP escrito uma vez pode ser reutilizado por qualquer host compatível.
✅ Tools do MCP funcionam para o modelo exatamente como tool use — o protocolo padroniza a descoberta e comunicação.
