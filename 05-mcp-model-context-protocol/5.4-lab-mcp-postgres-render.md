# 5.4 — Lab: um servidor MCP sobre um Postgres real

> Até aqui o servidor MCP devolvia dados de um dicionário em memória. Neste laboratório
> o dado sai de um **banco Postgres hospedado no Render**, inspecionado pelo **DBeaver**
> e exposto ao modelo por um **servidor MCP** — o caminho completo, ponta a ponta.

## O que você vai montar

```
Claude Code / Claude Desktop   →   servidor MCP (Python)   →   Postgres (Render)
        (host + client)              (5.4_servidor_...py)        (nuvem, TLS)
                                                ↑
                                          DBeaver (você, olhando o mesmo banco)
```

O DBeaver não faz parte do fluxo do agente: ele é a sua janela humana para o mesmo banco.
Serve para criar a tabela, conferir os dados e — mais importante — **checar se a resposta
que o modelo deu bate com a realidade**.

## Etapa 1 — Criar o Postgres no Render

1. Em [dashboard.render.com](https://dashboard.render.com), **New → Postgres**.
2. Preencha *Name*, *Database* e *User*, e escolha o plano **Free**.
3. Criado o banco, abra a aba **Connections**. Você vai usar a **External Database URL**
   (a *Internal* só funciona entre serviços dentro do Render — é o erro mais comum aqui).

O Render exige TLS em conexões que vêm de fora. É por isso que `sslmode=require` vai
aparecer tanto no DBeaver quanto no código Python.

> ⚠️ A External Database URL contém a senha em texto plano. Ela vai para o `.env`, nunca
> para o repositório. Confirme que `.env` está no `.gitignore`.

## Etapa 2 — Conectar o DBeaver e criar a tabela

1. **Database → New Database Connection → PostgreSQL**.
2. Preencha host, porta (5432), database, usuário e senha — todos estão na aba
   *Connections* do Render.
3. Aba **SSL** → marque **Use SSL** e defina *SSL mode* como `require`. Sem isso a conexão
   é recusada com um erro de rede genérico, difícil de diagnosticar.
4. **Test Connection** → na primeira vez o DBeaver oferece baixar o driver. Aceite.
5. Abra um editor SQL (`Ctrl+]`) e execute
   [`exemplos-python/5.4_seed.sql`](exemplos-python/5.4_seed.sql), que cria a tabela
   `cursos` com cinco linhas de exemplo.

Confira à esquerda, em `Schemas → public → Tables`, que `cursos` apareceu. Esse é o estado
de referência do lab.

## Etapa 3 — O servidor MCP

Código completo: [`exemplos-python/5.4_servidor_mcp_postgres.py`](exemplos-python/5.4_servidor_mcp_postgres.py)

```bash
pip install "mcp[cli]" "psycopg[binary]" python-dotenv
```

O servidor tem duas ferramentas, `listar_cursos` e `buscar_cursos_por_area`. Estruturalmente
é o mesmo servidor da aula 5.2 — decorator `@mcp.tool()`, docstring virando descrição,
assinatura virando schema. Muda só o miolo da função: em vez de ler um dicionário, ela abre
uma conexão e roda um `SELECT`.

Duas coisas valem atenção:

**A conexão é aberta dentro de cada ferramenta, não uma vez no topo do arquivo.** Um
servidor MCP fica ligado enquanto você conversa com o modelo, e pode passar bastante tempo
parado. O Postgres derruba conexões ociosas — uma conexão criada na inicialização morre em
silêncio e a primeira chamada depois da pausa falha.

**O parâmetro do SQL vai separado, com `%s`.** Nunca monte a query concatenando string
(`... WHERE area = '" + area + "'`). Aqui o valor vem do modelo, e o `psycopg` é quem trata
o conteúdo — essa é a defesa contra SQL injection.

## Etapa 4 — Testar antes de conectar

```bash
mcp dev exemplos-python/5.4_servidor_mcp_postgres.py
```

Isso abre o **MCP Inspector** numa página web local (normalmente `http://localhost:6274`).
Ele não é o seu servidor "em modo web": é um client MCP de mentira, que conversa com o seu
servidor e te deixa chamar as ferramentas na mão.

> ⚠️ **Pré-requisito escondido: Node.js.** O `mcp dev` chama `npx @modelcontextprotocol/inspector`
> por baixo — o Inspector é um pacote Node, não Python. Sem Node/npm instalado o comando
> falha com "npx não encontrado". Isso vale **só para o Inspector**: o servidor é Python
> puro, e a etapa 5 não precisa de Node. A primeira execução demora mais porque o `npx`
> baixa o Inspector na hora, e versões recentes exigem um token — copie do terminal a URL
> completa, com `?MCP_PROXY_AUTH_TOKEN=...`, não só o `localhost:6274`.

Na interface: **Connect** → aba **Tools** → **List Tools**. As duas ferramentas devem
aparecer com o schema derivado da assinatura Python. Rode `listar_cursos`, depois
`buscar_cursos_por_area` com `area="IA"`, e **compare com o que o DBeaver mostra**. Só
quando bater faz sentido conectar a um client de verdade — depurar erro de conexão através
de uma conversa com o modelo é bem mais lento.

## Etapa 5 — Conectar ao client

No Claude Code:

```bash
claude mcp add cursos -- python /caminho/absoluto/5.4_servidor_mcp_postgres.py
```

Caminho **absoluto**: o client sobe o servidor como subprocesso, e o diretório de trabalho
dele não é necessariamente o seu. Pelo mesmo motivo o `load_dotenv()` pode não achar o
`.env` — se isso acontecer, passe a variável direto com `--env DATABASE_URL=...`.

Verifique com `/mcp` que o servidor aparece conectado e pergunte algo como *"quais cursos
de IA estão disponíveis?"*. O modelo deve escolher `buscar_cursos_por_area` sozinho, a
partir da docstring.

No Claude Desktop, o equivalente é um bloco em `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "cursos": {
      "command": "python",
      "args": ["C:\\caminho\\absoluto\\5.4_servidor_mcp_postgres.py"],
      "env": { "DATABASE_URL": "postgresql://..." }
    }
  }
}
```

## Quando algo não funciona

| Sintoma | Causa provável |
|---|---|
| `connection refused` / timeout | Usou a *Internal* Database URL em vez da *External* |
| `SSL connection is required` | Faltou `sslmode=require` (no DBeaver, aba SSL) |
| `mcp dev` falha com "npx não encontrado" | Node.js não instalado — é dependência do Inspector, não do servidor |
| Inspector abre mas recusa a conexão | Faltou o `MCP_PROXY_AUTH_TOKEN` na URL; copie a linha inteira do terminal |
| Servidor some do `/mcp` logo após conectar | `DATABASE_URL` ausente derruba o processo já na inicialização |
| Banco sumiu depois de semanas | Plano free do Render expira; recrie e rode o seed de novo |

## Exercício

Crie uma terceira ferramenta, `cursos_ate_carga_horaria(maximo: int)`, que devolve os cursos
com carga horária menor ou igual ao valor informado. Teste no Inspector e depois pergunte ao
modelo, em linguagem natural, quais cursos cabem num fim de semana — e observe se ele
escolhe a ferramenta certa a partir da docstring que você escreveu.

## Pontos-Chave

✅ Um servidor MCP com banco real é o mesmo da aula 5.2 — muda só o miolo da função, que passa a rodar um `SELECT`.
✅ Use a *External* Database URL do Render, com `sslmode=require` no DBeaver e no código.
✅ O DBeaver é a sua conferência independente: valide as respostas do modelo contra ele.
✅ Abra a conexão dentro de cada ferramenta; conexão criada na inicialização morre por ociosidade.
✅ Passe parâmetros com `%s`, nunca concatenando string na query — o valor vem do modelo.
✅ Teste com `mcp dev` antes de conectar ao client; o Inspector precisa de Node.js, o servidor não.
