# 4.1 — Function Calling / Tool Use

> **Tool use (function calling)**: mecanismo pelo qual você descreve funções disponíveis
> para o modelo, e ele — em vez de só responder em texto — pode pedir para "chamar" uma
> dessas funções, com os parâmetros que julgar necessários.

## O que muda em relação a uma chamada normal

Até aqui, o modelo só gerava texto. Com tool use, você declara um conjunto de ferramentas
(nome, descrição, schema de parâmetros) e o modelo pode responder com um pedido de
**chamada de função** em vez de texto — cabe ao seu código executar essa função de verdade
e devolver o resultado para o modelo continuar.

Importante: **o modelo nunca executa código**. Ele só decide "eu preciso da ferramenta X
com esses parâmetros" — quem roda a função é sempre o seu programa.

## Anatomia de uma ferramenta

```python
{
    "name": "consultar_temperatura",
    "description": "Retorna a temperatura atual de uma cidade. Chame esta ferramenta "
                    "sempre que o usuário perguntar sobre o clima de um lugar específico.",
    "input_schema": {
        "type": "object",
        "properties": {
            "cidade": {"type": "string", "description": "Nome da cidade, ex: 'São Paulo'"},
        },
        "required": ["cidade"],
    },
}
```

A **`description`** é o campo mais importante — é com base nela que o modelo decide
**quando** chamar a ferramenta. Descrições vagas levam a chamadas em momentos errados (ou
a não chamar quando deveria). Seja específico sobre o gatilho: "chame quando o usuário
perguntar sobre X" é melhor que apenas "retorna a temperatura".

## O ciclo de uma chamada com tool use

```
1. Você envia a pergunta + a lista de ferramentas disponíveis
2. O modelo responde com stop_reason="tool_use" e um bloco tool_use (nome + parâmetros)
3. Seu código executa a função de verdade com esses parâmetros
4. Você envia o resultado de volta como um bloco tool_result
5. O modelo gera a resposta final em texto, agora com o resultado disponível
```

## Exemplo em Python — ciclo completo

Código completo: [`exemplos-python/4.1_function_calling_basico.py`](exemplos-python/4.1_function_calling_basico.py)

```python
response = client.messages.create(
    model="claude-haiku-4-5",
    max_tokens=300,
    tools=tools,
    messages=messages,
)

if response.stop_reason == "tool_use":
    tool_use_block = next(b for b in response.content if b.type == "tool_use")
    resultado = consultar_temperatura(**tool_use_block.input)

    messages.append({"role": "assistant", "content": response.content})
    messages.append({
        "role": "user",
        "content": [{"type": "tool_result", "tool_use_id": tool_use_block.id, "content": resultado}],
    })
```

Note que o `tool_use_id` da resposta do modelo precisa ser ecoado de volta no
`tool_result` — é assim que o modelo sabe a qual chamada aquele resultado corresponde.

## Erros comuns

| Erro | Consequência |
|---|---|
| Descrição vaga da ferramenta | Modelo chama no momento errado, ou nunca chama |
| Esquecer de reenviar `response.content` completo | Perde o bloco `tool_use`, próxima chamada falha |
| Não tratar `is_error` no resultado | Modelo não sabe que a ferramenta falhou e pode alucinar um resultado |
| Schema de parâmetros incompleto | Modelo pode enviar parâmetros em formato inesperado |

## Pontos-Chave

✅ O modelo nunca executa código — ele só pede para chamar a função, seu programa executa.
✅ A `description` da ferramenta é o principal sinal para o modelo decidir quando usá-la.
✅ O ciclo é sempre: pergunta → pedido de chamada → execução → resultado → resposta final.
✅ Sempre ecoe o `tool_use_id` correto no `tool_result` correspondente.
