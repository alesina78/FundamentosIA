# 4.2 — Loops Agentic e Padrão ReAct

> **Loop agentic**: em vez de uma única troca pergunta→ferramenta→resposta, o modelo pode
> encadear várias chamadas de ferramenta em sequência, usando o resultado de uma para
> decidir a próxima ação, até ter informação suficiente para responder.

## Da chamada única ao loop

Na aula 4.1 vimos um ciclo de duas chamadas: pergunta → tool_use → tool_result → resposta.
Mas e se a resposta exigir **várias** ferramentas em sequência, onde uma depende do
resultado da anterior? Um "agente" nada mais é do que colocar esse ciclo dentro de um loop
que continua até o modelo sinalizar que não precisa mais de ferramentas
(`stop_reason != "tool_use"`).

## O padrão ReAct (Reasoning + Acting)

ReAct é o nome dado a esse padrão de raciocínio intercalado com ação:

```
Raciocinar → o que preciso fazer para responder isso?
Agir       → chamar a ferramenta necessária
Observar   → ver o resultado da ferramenta
(repetir até ter informação suficiente)
Responder  → gerar a resposta final em texto
```

Isso é exatamente o que a API da Anthropic faz de forma nativa com tool use: cada iteração
do loop é um "raciocinar + agir", e o `tool_result` que você devolve é a "observação".

## Exemplo em Python — loop agentic com múltiplas ferramentas

Código completo: [`exemplos-python/4.2_loop_agentic_react.py`](exemplos-python/4.2_loop_agentic_react.py)

```python
def resolver_com_loop_agentic(pergunta: str, max_iteracoes: int = 5) -> str:
    messages = [{"role": "user", "content": pergunta}]

    for _ in range(max_iteracoes):
        response = client.messages.create(
            model="claude-haiku-4-5", max_tokens=500, tools=tools, messages=messages,
        )

        if response.stop_reason != "tool_use":
            return next(b.text for b in response.content if b.type == "text")

        messages.append({"role": "assistant", "content": response.content})
        tool_results = [...]  # executa cada tool_use do turno
        messages.append({"role": "user", "content": tool_results})

    return "Não foi possível resolver dentro do limite de iterações."
```

Rode o exemplo com a pergunta "some 4 com 6, depois multiplique o resultado por 3" — o
modelo vai chamar `somar`, receber o resultado (10), decidir que precisa chamar
`multiplicar(10, 3)`, e só então responder com o valor final.

## Por que ter um `max_iteracoes`

Sem um limite de iterações, um agente mal comportado (ou uma tarefa mal especificada) pode
entrar em loop indefinido, gerando custo sem chegar a lugar nenhum. Sempre defina um teto —
se atingido, trate como falha explícita em vez de deixar o loop rodar sem controle.

## Riscos de agentes com loops

| Risco | Mitigação |
|---|---|
| Loop infinito / custo descontrolado | `max_iteracoes` + monitorar tokens gastos |
| Ação irreversível (deletar dado, enviar email) | Ferramentas de alto risco exigem confirmação humana antes de executar |
| Ferramenta retorna erro e o modelo "insiste" | Tratar `is_error: true` no `tool_result` para o modelo saber que falhou |
| Ferramentas paralelas com efeitos colaterais conflitantes | Cuidado ao permitir múltiplas chamadas no mesmo turno se elas não forem independentes |

## Pontos-Chave

✅ Um loop agentic repete o ciclo tool_use → tool_result até o modelo não precisar mais de ferramentas.
✅ ReAct é o padrão conceitual de "raciocinar → agir → observar" repetido.
✅ Sempre limite o número de iterações para evitar loops descontrolados e custo excessivo.
✅ Ações irreversíveis dentro de um loop agentic merecem confirmação humana antes de executar.
