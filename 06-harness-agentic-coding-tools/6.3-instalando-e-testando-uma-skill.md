# 6.3 — Instalando e testando uma Skill

> **Skill**: um pacote de instruções (e opcionalmente scripts e arquivos de apoio) para uma
> tarefa específica, que o agente carrega **sob demanda**, só quando percebe que é relevante.

## O problema que a skill resolve

Toda instrução que você coloca no prompt principal ou no `CLAUDE.md` ocupa contexto **o tempo
todo** — mesmo nas 95% das sessões em que ela não tem nada a ver com o que você está fazendo.
Como vimos na aula 1.2, contexto é um recurso finito e caro: encher a janela com procedimentos
irrelevantes degrada o desempenho nas tarefas que importam.

A skill inverte isso. O agente enxerga permanentemente só uma linha por skill — nome e
descrição — e carrega o conteúdo completo apenas quando a descrição bate com a tarefa atual.

```
Sem skill: as 40 linhas de "como gerar o relatório mensal no padrão da empresa"
           moram no CLAUDE.md e são lidas em toda sessão, inclusive quando você
           só quer corrigir um typo.

Com skill: o agente vê "relatorio-mensal: gera o relatório no padrão da empresa"
           e só abre as 40 linhas quando você pede um relatório.
```

Isso é o mesmo princípio do RAG (módulo 3) — recuperar sob demanda em vez de carregar tudo —
aplicado a **procedimentos** em vez de fatos. A descrição da skill faz o papel do índice.

## Anatomia de uma skill

Uma skill é uma pasta com um `SKILL.md` dentro, com frontmatter YAML:

```
.claude/skills/
└── revisor-de-pr/
    ├── SKILL.md          ← instruções + frontmatter (nome e descrição)
    ├── checklist.md      ← recursos auxiliares, carregados só se citados
    └── scripts/
        └── diff_stats.py
```

```yaml
---
name: revisor-de-pr
description: Revisa um pull request buscando bugs de correção e problemas de estilo.
             Use quando o usuário pedir review de PR, diff ou branch.
---
```

O campo `description` é a parte crítica e a mais malfeita na prática: é **a única coisa** que
o agente lê antes de decidir carregar a skill. Ela precisa dizer o que a skill faz *e em quais
situações usá-la* — descrição vaga significa skill que nunca dispara ou que dispara na hora
errada.

O escopo segue o mesmo padrão dos hooks: `~/.claude/skills/` vale para tudo, `.claude/skills/`
do projeto vale só ali (e versiona junto com o repositório, disponível para o time inteiro).

## Instalando uma skill do SkillsMP

O [SkillsMP](https://skillsmp.com/) é um marketplace da comunidade com skills prontas,
organizadas por categoria. Serve para dois fins: reaproveitar trabalho já testado e estudar
como outras pessoas estruturam suas skills.

O fluxo de instalação, em qualquer catálogo:

1. **Escolher** a skill no catálogo e ler a descrição do que ela promete fazer.
2. **Ler o conteúdo do `SKILL.md` antes de instalar.** Uma skill é instrução executável que
   entra no seu contexto e pode trazer scripts junto — é código de terceiros, trate como tal.
3. **Copiar a pasta** para `~/.claude/skills/` (uso pessoal) ou `.claude/skills/` (projeto).
4. **Reiniciar a sessão** para o agente reindexar as skills disponíveis.
5. **Verificar** que ela aparece na lista de skills disponíveis.

> ⚠️ Skill de terceiros é superfície de ataque real: instruções maliciosas dentro de um
> `SKILL.md` são um vetor de prompt injection persistente. Ler antes de instalar não é
> paranoia, é o mínimo. Voltamos ao tema na aula 6.5.

## Testando uma skill

O teste de uma skill tem duas perguntas independentes, e confundi-las é a fonte de quase toda
frustração com skills.

**Pergunta 1 — ela dispara?** Faça um pedido em linguagem natural que *deveria* acionar a
skill, sem citá-la pelo nome, e observe se o agente a carrega. Se não disparar, o problema
está quase sempre na `description`: ela não contém as palavras e situações que você de fato
usa ao pedir. Faça também o teste negativo — um pedido próximo mas diferente, que **não**
deveria acionar a skill. Skill que dispara sempre é só CLAUDE.md com passos extras.

**Pergunta 2 — o resultado é bom?** Só depois que ela dispara faz sentido avaliar a qualidade
das instruções. Aqui o ajuste é no corpo do `SKILL.md`, não no frontmatter.

Se precisar isolar a segunda pergunta da primeira, invoque a skill explicitamente pelo nome —
assim você testa o conteúdo sem depender do gatilho.

## Skill, hook ou CLAUDE.md?

| Você quer... | Use |
|---|---|
| Uma regra que **sempre** vale, sem exceção | Hook (aula 6.2) |
| Uma convenção curta e onipresente do projeto | `CLAUDE.md` |
| Um procedimento longo, usado só às vezes | **Skill** |

## Pontos-Chave

✅ Skill = instruções carregadas sob demanda; é o princípio do RAG aplicado a procedimentos.
✅ É uma pasta com `SKILL.md`, em `~/.claude/skills/` (global) ou `.claude/skills/` (projeto).
✅ A `description` é o índice — é ela que decide se a skill dispara ou não.
✅ Skills do SkillsMP economizam trabalho, mas são código de terceiros: leia antes de instalar.
✅ Teste em duas etapas separadas: se ela **dispara** (frontmatter) e se o **resultado é bom** (corpo).
