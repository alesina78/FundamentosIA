# 7.2 — Hooks, Skills e Subagents

> Três mecanismos de extensão que harnesses como o Claude Code oferecem para customizar e
> especializar o comportamento do agente além do loop agentic básico (aula 7.1).

## Hooks — interceptar o ciclo do agente

Um **hook** é um ponto de extensão que executa código customizado (seu, não do modelo) em
momentos específicos do ciclo do agente — por exemplo, antes de uma ferramenta ser
executada, depois que ela termina, ou quando o agente conclui uma tarefa. Hooks rodam
**determinísticamente**, fora do controle do LLM — são a forma de garantir que uma regra
sempre seja aplicada, sem depender do modelo "lembrar" de segui-la.

Usos comuns de hooks:
- **Auditoria**: logar toda ação executada pelo agente.
- **Bloqueio automático**: impedir escrita em arquivos sensíveis, independente do que o modelo decidiu.
- **Formatação automática**: rodar um linter/formatter depois de cada edição de arquivo.
- **Notificação**: avisar o usuário quando uma tarefa terminar.

## Exemplo em Python — simulando um hook pré-execução

Código completo: [`exemplos-python/7.2_hook_pre_execucao.py`](exemplos-python/7.2_hook_pre_execucao.py)

```python
def hook_pre_tool_use(nome_ferramenta: str, entrada: dict) -> tuple[bool, str | None]:
    # 1. Log de auditoria — toda chamada de ferramenta fica registrada.
    with open(LOG_PATH, "a", encoding="utf-8") as f:
        f.write(f"{datetime.now().isoformat()} | {nome_ferramenta} | {json.dumps(entrada)}\n")

    # 2. Bloqueio automático de arquivos sensíveis, independente do que o modelo decidiu.
    if nome_ferramenta == "escrever_arquivo":
        if any(protegido in entrada.get("nome_arquivo", "") for protegido in ARQUIVOS_PROTEGIDOS):
            return False, f"Bloqueado por hook: arquivo protegido."
    return True, None
```

O ponto central: essa checagem **não depende do modelo se comportar bem** — o hook bloqueia
mesmo que o modelo tenha decidido (por erro ou manipulação) escrever num arquivo protegido.
No Claude Code, hooks reais são configurados declarativamente (via `settings.json`), sem
precisar escrever esse código de interceptação na mão — o exemplo acima só ilustra o
mecanismo por trás.

## Skills — instruções especializadas carregadas sob demanda

Uma **skill** é um pacote de instruções (e opcionalmente scripts/recursos) para uma tarefa
específica, que o agente carrega **somente quando relevante** — em vez de colocar tudo no
prompt principal o tempo todo (o que gastaria contexto à toa, ver módulo 1.2).

```
Sem skills: todo o conhecimento sobre "como gerar um relatório em Excel formatado
            do jeito da empresa" fica sempre no prompt, mesmo quando a tarefa não
            tem nada a ver com isso.

Com skills: essa instrução vive numa skill separada, e só é carregada quando o
            agente identifica que a tarefa atual precisa dela.
```

Isso é o mesmo princípio de "carregar contexto sob demanda" que vimos com RAG (módulo 3) —
só que aplicado a instruções e procedimentos, não a fatos.

Você pode escrever suas próprias skills do zero, ou explorar skills prontas feitas pela
comunidade em catálogos como o [SkillsMP](https://skillsmp.com/) — um marketplace de
skills para Claude Code, organizado por categoria, útil tanto para reaproveitar skills
já testadas quanto para ter referência de como estruturar as suas.

## Subagents — delegação especializada

Um **subagent** é uma instância separada do agente, com seu próprio contexto e propósito,
que o agente principal pode invocar para uma sub-tarefa específica — o mesmo conceito de
multi-agente (aula 4.3), mas integrado nativamente ao harness. Útil para:

- Isolar uma sub-tarefa que não precisa "poluir" o contexto principal com detalhes (ex: uma busca extensa no código).
- Rodar sub-tarefas independentes em paralelo.
- Aplicar um conjunto de ferramentas/permissões diferente para uma sub-tarefa específica (ex: um subagent "revisor" que só tem permissão de leitura).

## Comparando os três mecanismos

| Mecanismo | O que resolve | Quem controla |
|---|---|---|
| **Hook** | Garantir uma regra sempre é aplicada, sem depender do modelo | Seu código (determinístico) |
| **Skill** | Carregar conhecimento especializado só quando necessário | O agente decide quando carregar |
| **Subagent** | Isolar/paralelizar sub-tarefas com contexto e permissões próprios | O agente principal decide quando delegar |

## Pontos-Chave

✅ Hooks rodam código determinístico em pontos do ciclo — garantem regras que não dependem do modelo "se comportar".
✅ Skills carregam instruções especializadas sob demanda, economizando contexto.
✅ Subagents delegam sub-tarefas a instâncias com contexto e permissões próprios.
✅ Os três mecanismos resolvem problemas diferentes e são usados em conjunto, não como alternativas entre si.
