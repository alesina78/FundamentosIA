# 1.2 — Tokens, Context Window e Custos

> **Token**: a unidade mínima de texto que um LLM processa — geralmente um pedaço de
> palavra, não uma palavra inteira. Em português, 1 token ≈ 3-4 caracteres em média.

## Por que tokens importam

Todo LLM tem três limites diretamente ligados a tokens:

1. **Context window**: quantos tokens (entrada + saída) o modelo consegue processar de
   uma vez. Se sua conversa + documentos ultrapassarem esse limite, ela precisa ser
   cortada, resumida ou tratada com RAG (módulo 3).
2. **Custo**: provedores cobram por token, geralmente com preços diferentes para tokens de
   entrada (input) e saída (output).
3. **Latência**: mais tokens de saída = mais tempo de resposta, porque o modelo gera um
   token de cada vez.

## Contando tokens sem escrever código

Antes de automatizar nada, vale visualizar como um texto é dividido em tokens. Cole um
trecho de texto em português no **tokenizer** público da OpenAI e observe a contagem e a
divisão:

🔗 [platform.openai.com/tokenizer](https://platform.openai.com/tokenizer) — tokenizador
público que permite colar qualquer texto e ver, visualmente, como ele é fatiado em tokens
e quantos tokens resultam. É o tokenizer da OpenAI, não do Claude — a Anthropic não
disponibiliza um tokenizer público standalone equivalente — mas o comportamento geral
(fatiar texto em pedaços de palavra) é o mesmo entre provedores, e serve bem para ganhar
intuição visual antes de contar tokens do Claude via API.

**Experimente:**
1. Cole a frase "Quantos tokens tem esse texto em português?" e veja a contagem.
2. Compare o mesmo texto traduzido em português e em inglês e veja qual consome mais
   tokens. O resultado pode variar bastante dependendo do texto específico — não assuma
   uma regra fixa, teste você mesmo antes de tirar conclusões (ex: acentuação, palavras
   compostas e certas construções em português podem gerar mais tokens em alguns casos,
   mas nem sempre).
3. Cole um trecho de código Python e observe como a contagem por caractere muda em
   relação a texto corrido.

Para ver a contagem oficial de tokens do Claude sem escrever código, use o **Workbench**
em [console.anthropic.com](https://console.anthropic.com/): escreva um prompt, clique em
**Run**, e a contagem de tokens de entrada e saída aparece junto com a resposta (não é uma
contagem "ao vivo" enquanto você digita).

Para contagem exata programaticamente, use `client.messages.count_tokens` do SDK antes de
enviar requisições grandes em produção — isso evita estourar o context window e permite
estimar custo previamente.

## Estimando custo de uma chamada

Código completo: [`exemplos-python/1.2_estimar_custo.py`](exemplos-python/1.2_estimar_custo.py)

```python
def estimar_custo(tokens_input: int, tokens_output: int) -> float:
    custo_input = (tokens_input / 1_000_000) * PRECO_INPUT_POR_MTOK
    custo_output = (tokens_output / 1_000_000) * PRECO_OUTPUT_POR_MTOK
    return round(custo_input + custo_output, 6)
```

## O que fazer quando o conteúdo não cabe no context window

| Estratégia | Quando usar |
|---|---|
| Resumir histórico antigo | Conversas longas onde o início já não é crítico |
| RAG (buscar só o relevante) | Base de conhecimento grande, você não precisa de tudo de uma vez |
| Truncar (cortar o mais antigo) | Simples, mas perde informação — usar com cautela |
| Usar um modelo com context window maior | Quando o conteúdo realmente precisa estar inteiro |

## Pontos-Chave

✅ Tokens ≠ palavras — em português a razão é ~1 token a cada 3-4 caracteres.
✅ Context window limita input + output combinados, não só um dos dois.
✅ Custo é cobrado por token, com preços diferentes para input e output.
✅ Sempre conte tokens antes de enviar payloads grandes para evitar erros e custo surpresa.
