# 1.3 — Limitações, Alucinações e Quando Desconfiar

> **Alucinação**: quando um LLM gera uma informação que soa plausível e confiante, mas é
> factualmente incorreta ou inventada.

## Por que LLMs alucinam

O modelo foi treinado para gerar a continuação **mais plausível**, não a mais **verdadeira**.
Quando ele não tem informação suficiente sobre um fato (uma API específica, uma versão de
biblioteca, um evento recente), ele ainda assim vai gerar algo — porque gerar texto
plausível é literalmente o que ele faz. Não existe um mecanismo interno de "não sei".

## Situações de alto risco de alucinação

| Situação | Por quê |
|---|---|
| Fatos muito específicos (números, datas, nomes) | Baixa frequência no treino, fácil de confundir com algo parecido |
| Eventos após o corte de conhecimento do modelo | O modelo não tem essa informação de forma alguma |
| Nomes de funções/parâmetros de bibliotecas | Tende a "inventar" uma API plausível parecida com outras que viu |
| Citações e referências bibliográficas | Frequentemente inventa títulos/autores plausíveis |
| Cálculos matemáticos complexos | LLMs não são calculadoras — preferem prever um número plausível |

## Exemplo em Python — comparando duas respostas do mesmo modelo

Código completo: [`exemplos-python/1.3_comparando_temperature.py`](exemplos-python/1.3_comparando_temperature.py)

```python
def perguntar(pergunta: str, temperature: float = 1.0) -> str:
    r = client.messages.create(
        model="claude-haiku-4-5",
        max_tokens=200,
        temperature=temperature,
        messages=[{"role": "user", "content": pergunta}],
    )
    return r.content[0].text

pergunta = "Qual foi o placar da final de um campeonato fictício que não existe?"
print(perguntar(pergunta))
# Um LLM mal orientado pode "inventar" um placar em vez de dizer que não existe informação.
```

Um prompt melhor reduz (mas não elimina) o risco:

Código completo: [`exemplos-python/1.3_prompt_com_permissao_para_nao_saber.py`](exemplos-python/1.3_prompt_com_permissao_para_nao_saber.py)

```python
pergunta_melhor = (
    "Qual foi o placar da final de um campeonato fictício que não existe? "
    "Se você não tiver certeza ou a informação não existir, diga explicitamente "
    "que não sabe, em vez de inventar uma resposta."
)
print(perguntar(pergunta_melhor, temperature=0))
```

## Estratégias de mitigação

1. **Peça a fonte**: instrua o modelo a citar de onde tirou a informação (ou dizer que não sabe).
2. **Reduza `temperature`** para tarefas factuais (mais determinístico, menos "criativo").
3. **Use RAG** para ancorar respostas em documentos reais (módulo 3).
4. **Valide programaticamente** saídas críticas (ex: rodar o código gerado, checar contra um schema).
5. **Nunca confie cegamente** em números, citações ou nomes de API sem checar a fonte.

## Pontos-Chave

✅ Alucinação não é um "bug raro" — é uma consequência direta de como o modelo gera texto.
✅ Fatos específicos, eventos recentes e nomes de API são pontos de alto risco.
✅ Pedir a fonte, baixar `temperature` e usar RAG reduzem — mas não eliminam — o risco.
✅ Toda saída crítica de um LLM deve ter algum tipo de verificação humana ou programática.
